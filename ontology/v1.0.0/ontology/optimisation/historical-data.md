# Optimisation: HistoricalPilotData, HistoricalMarketData

## Overview

This module defines TUM's historical data aggregation classes, which provide the time-series datasets used for FOS model training, validation, and retrospective analysis.

**Partners:** TUM

---

## HistoricalPilotData

**Contributing partners:** TUM
**Standard mappings:** SOSA `ObservationCollection`, OGC Time series, DCAT `Dataset`, SEAS `Evaluation`

A container of time-series datasets capturing historical physical measurements from a pilot site. Used by TUM's FOS module for training machine learning models (demand forecasting, generation prediction, thermal modelling) and for retrospective validation.

### Attributes

| Attribute | Type | Required | Description | Standard Mapping |
|-----------|------|----------|-------------|-----------------|
| `loadTimeSeries` | TimeSeries | No | Historical aggregate electrical load at the pilot | SOSA `ObservationCollection`, IEC 61850 `MMXU.W` |
| `pvPowerTimeSeries` | TimeSeries | No | Historical PV generation power | SOSA `ObservationCollection`, IEC 61850 `MMXU.W` |
| `avgHpPowerTimeSeries` | TimeSeries | No | Historical average heat pump power | SOSA `ObservationCollection`, IEC 61850 `MMXU.W` |
| `avgWhPowerTimeSeries` | TimeSeries | No | Historical average water heater power | SOSA `ObservationCollection`, IEC 61850 `MMXU.W` |
| `tDhwCTimeSeries` | TimeSeries | No | Historical domestic hot water temperature | SOSA `ObservationCollection`, IEC 61850 `STMP.Tmp` |
| `tIndoorCTimeSeries` | TimeSeries | No | Historical indoor air temperature | SOSA `ObservationCollection`, IEC 61850 `STMP.Tmp` |
| `evUsageTimeSeries` | TimeSeries | No | Historical EV charging power or session data | SOSA `ObservationCollection`, IEC 61850 `MMXU.W` |
| `hydroPowerTimeSeries` | TimeSeries | No | Historical hydroelectric generation power | SOSA `ObservationCollection`, IEC 61850 `MMXU.W` |

### TimeSeries Type

`TimeSeries` is not a standalone ontology class; it represents a sequence of `(timestamp, value)` pairs. The recommended representation is:

```json
{
  "resolution": "PT15M",
  "unit": "kW",
  "values": [
    { "ts": "2026-01-01T00:00:00Z", "v": 12.4 },
    { "ts": "2026-01-01T00:15:00Z", "v": 11.8 }
  ]
}
```

Aligned with SOSA `ObservationCollection` and OGC Moving Features / Time Series Profile.

### Relationships

| Relationship | Target | Cardinality | Description |
|-------------|--------|-------------|-------------|
| `describes` | Pilot | many to 1 | The pilot site this historical dataset covers |

### Validation Rules

- All `TimeSeries` values within a `HistoricalPilotData` record must share the same temporal resolution (e.g. all 15-minute intervals).
- Timestamps must be in ISO 8601 UTC format.
- Missing observations within a series must be represented as `null` values (not omitted) to preserve alignment.

### Notes

- Historical data availability varies by pilot: the LIC and Aran Islands pilots have the most complete datasets; the Lucerne site has size limitations; Greenvolt had no usable datasets at the time of writing.
- These datasets are used to train FOS ML models. Per the INTELLIGENT data management plan, data must be managed in accordance with GDPR and FAIR principles. Pilot sites are the data controllers for site-level datasets.

## HistoricalMarketData

**Contributing partners:** TUM
**Standard mappings:** SOSA `ObservationCollection`, DCAT `Dataset`, CIM `MarketDocument` historical

A container of time-series datasets capturing historical market outcomes, used for retrospective validation of the GSY DEX trading algorithms and FOS trading strategy performance.

### Attributes

| Attribute | Type | Required | Description | Standard Mapping |
|-----------|------|----------|-------------|-----------------|
| `tradeTimeSeries` | TimeSeries | No | Historical sequence of executed trades (price, quantity, timestamp) | CIM `MarketAgreement`, OGC Time series |
| `marketOutcomeTimeSeries` | TimeSeries | No | Historical clearing results per market slot (clearing price, volumes) | CIM `MarketDocument`, OGC Time series |

### Relationships

| Relationship | Target | Cardinality | Description |
|-------------|--------|-------------|-------------|
| `describes` | Pilot | many to 1 | The pilot site whose market history this covers |

### Validation Rules

- Timestamps must be in ISO 8601 UTC format.
- `tradeTimeSeries` entries should align with `Market` delivery slots.
- `marketOutcomeTimeSeries` should have one entry per market clearing run.

### Notes

- Market data is generated by the GSY DEX. TUM aggregates it into time-series format for FOS retrospective analysis.
- Per the INTELLIGENT data management plan, market data classified as SEN/OA (sensitive but potentially open with anonymisation) must be handled accordingly before sharing outside the consortium.
