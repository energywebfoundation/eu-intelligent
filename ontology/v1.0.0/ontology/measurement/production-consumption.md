# Measurement: Production, Consumption

## Overview

`Production` and `Consumption` are aggregated energy measurement records associated with an `Asset` over a defined time period. They are the primary source of billing inputs and market clearing validation data.

**Partners:** R2M

---

## Production

**Contributing partners:** R2M
**Standard mappings:** SOSA `Observation`, SAREF `Measurement`, DLMS-COSEM `Register` (class_id 3), CIM `MeterReading`

An aggregated record of energy produced by an `Asset` over a defined period. Production records are generated by aggregating raw measurements from smart meters, inverter APIs, or data loggers, and stored for use in billing, market settlement, and FOS historical analysis.

### Attributes

| Attribute | Type | Required | Description | Standard Mapping |
|-----------|------|----------|-------------|-----------------|
| `productionId` | UUID | Yes | Unique identifier | CIM `IdentifiedObject.mRID` |
| `assetId` | UUID | Yes | Asset that produced the energy | CIM `IdentifiedObject.mRID` |
| `aggregationPeriod` | string | Yes | Duration of the aggregation window (ISO 8601 duration) | OGC Time `Interval` |
| `aggregationType` | string | Yes | Method of aggregation applied | SOSA `ObservationCollection` |
| `value` | number | Yes | Aggregated energy value | SOSA `hasSimpleResult` |
| `unit` | string | Yes | Unit of measurement | QUDT / IEC 61850 unit codes |
| `timestamp` | timestamp | Yes | End timestamp of the aggregation period | OGC Time `Instant` |

### `aggregationPeriod` Values (ISO 8601 Duration)

| Value | Description |
|-------|-------------|
| `PT15M` | 15-minute interval |
| `PT30M` | 30-minute interval |
| `PT1H` | 1-hour interval |
| `P1D` | Daily |
| `P1M` | Monthly |

### `aggregationType` Values

| Value | Description |
|-------|-------------|
| `sum` | Sum of all measurements in the period |
| `average` | Mean of all measurements in the period |
| `max` | Maximum value in the period |
| `min` | Minimum value in the period |

### `unit` Values

| Value | Description | DLMS-COSEM Unit |
|-------|-------------|-----------------|
| `kWh` | Kilowatt-hours (energy) | Unit code 30 |
| `kW` | Kilowatts (power average) | Unit code 27 |
| `Wh` | Watt-hours | Unit code 30 (scale -3) |

### Relationships

| Relationship | Target | Cardinality | Description |
|-------------|--------|-------------|-------------|
| `belongs to` | Asset | many to 1 | Asset that produced this energy |

### Validation Rules

- `productionId` must be a valid RFC 4122 UUID.
- `assetId` must reference an existing `Asset.assetId`.
- `assetId` must reference an asset of a generation type (`assetType` in `pv_system`, `hydro_power_plant`).
- `aggregationPeriod` must be a valid ISO 8601 duration string.
- `aggregationType` must be one of the enumerated values above.
- `value` must be non-negative.
- `unit` must be one of the enumerated values above.
- `timestamp` marks the **end** of the aggregation window (convention: energy registered at period close).

### DLMS-COSEM Mapping

| Attribute | DLMS-COSEM Object |
|-----------|------------------|
| Energy yield (daily) | `1.0.2.8.0.255` (Export active energy, Total, daily profile) |
| Energy yield (15-min) | `1.0.2.5.0.255` (Export active demand register, 15-min) |

## Consumption

**Contributing partners:** R2M
**Standard mappings:** SOSA `Observation`, SAREF `Measurement`, DLMS-COSEM `Register` (class_id 3), CIM `MeterReading`

An aggregated record of energy consumed by an `Asset` over a defined period. Structurally identical to `Production`; the semantic difference is that consumption records energy flowing into a device or site rather than out.

### Attributes

| Attribute | Type | Required | Description | Standard Mapping |
|-----------|------|----------|-------------|-----------------|
| `consumptionId` | UUID | Yes | Unique identifier | CIM `IdentifiedObject.mRID` |
| `assetId` | UUID | Yes | Asset that consumed the energy | CIM `IdentifiedObject.mRID` |
| `aggregationPeriod` | string | Yes | Aggregation window duration (ISO 8601 duration) | OGC Time `Interval` |
| `aggregationType` | string | Yes | Aggregation method | SOSA `ObservationCollection` |
| `value` | number | Yes | Aggregated energy value | SOSA `hasSimpleResult` |
| `unit` | string | Yes | Unit of measurement | QUDT / IEC 61850 unit codes |
| `timestamp` | timestamp | Yes | End timestamp of the aggregation period | OGC Time `Instant` |

### Relationships

| Relationship | Target | Cardinality | Description |
|-------------|--------|-------------|-------------|
| `belongs to` | Asset | many to 1 | Asset that consumed this energy |

### Validation Rules

All validation rules are identical to `Production`, with the following differences:
- `assetId` must reference an asset of a consuming or storage type (`assetType` in `load`, `battery`, `ev_charging_station`, `heat_pump`, `water_heater`, `boiler`).
- `value` must be non-negative.

### DLMS-COSEM Mapping

| Attribute | DLMS-COSEM Object |
|-----------|------------------|
| Energy consumption (daily) | `1.0.1.8.0.255` (Import active energy, Total, daily profile) |
| Energy consumption (15-min) | `1.0.1.5.0.255` (Import active demand register, 15-min) |

### Notes

- `Production` and `Consumption` are symmetric classes. In the ER diagram they are modelled as arrays on `Asset` (`productionList`, `consumptionList`), but in practice they are stored as individual records keyed by `assetId` and `timestamp`.
- For bidirectional assets (e.g. BESS that both charges and discharges), separate `Production` and `Consumption` records are created for the same interval to represent each direction independently.
